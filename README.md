# 家計簿アプリ

夫婦でも個人でも使える、シンプルな家計簿の Web アプリです。
**「今いくら使っていて、あといくら使えるか」** が一目で分かることを最優先に作っています。

- **メールアドレスもパスワードも使いません。** 2人で決めた「合言葉」とお名前だけで始められます
- **開いてすぐ入力画面。** 一番左のタブが入力欄です
- iPhone を最優先にしたモバイルファースト設計
- ホーム画面に追加してアプリのように使える（PWA）
- 夫婦2人でデータを共有する「共有モード」と、1人で使う「個人モード」
- 日本語・日本円・日本時間

## 1. まず試してみる（登録不要）

Supabase の設定をしなくても、**デモモード**でほぼ全ての機能を試せます。

```bash
npm install --prefix kakeibo
npm run dev --prefix kakeibo
```

ブラウザで <http://localhost:3000> を開き、最初の画面の「**デモモードで見る**」を押してください。
サンプルの家計データ（夫婦2人・3ヶ月分の支出・貯金目標・コメント・Todo）が入った状態で始まります。

> デモモードのデータは、その端末のブラウザ内（localStorage）にだけ保存されます。
> パートナーとの共有や、他の端末からの閲覧はできません。本番利用には Supabase の設定が必要です。

## 3. Supabase の作成・設定方法

### 3-1. プロジェクトを作る

1. <https://supabase.com/> を開き、右上の「Start your project」からアカウントを作ります（GitHub アカウントでもメールでも可）。
2. ログインしたら「**New project**」を押します。
3. 次の項目を入力します。
   - **Name**: `kakeibo`（好きな名前で構いません）
   - **Database Password**: 自動生成のものを使い、**必ず控えておいてください**
   - **Region**: `Northeast Asia (Tokyo)` を選ぶと日本から速くなります
4. 「Create new project」を押し、準備が終わるまで1〜2分待ちます。

### 3-2. データベースを作る（SQL を貼り付けるだけ）

左メニューの「**SQL Editor**」を開き、このリポジトリの `supabase/migrations/` にある
**4つのファイルを、番号順に1つずつ**貼り付けて実行（Run）します。

| 順番 | ファイル | 内容 |
| --- | --- | --- |
| 1 | `0001_schema.sql` | テーブル（データの入れ物）を作る |
| 2 | `0002_functions.sql` | 合言葉での参加・パートナー解除などの処理と初期カテゴリを登録 |
| 3 | `0003_rls.sql` | **セキュリティ設定（他人にデータを見せないための鍵）** |
| 4 | `0004_realtime.sql` | パートナーの変更をリアルタイムに反映する設定 |

> ⚠️ **3番の `0003_rls.sql` は必ず実行してください。** これがないと、他の人のデータが見えてしまいます。

> 📌 **すでに 0001〜0004 を実行したあとに更新した場合**は、追加で
> `0005_shared_payer_and_comment_reactions.sql` も実行してください。
> （共有の支出を個人に加算しない変更と、コメントの返信・いいねの追加分です。
> これから新しく作る場合は 0001〜0004 に同じ内容が入っているため不要です）

各ファイルの実行後に「Success. No rows returned」と表示されれば成功です。

<details>
<summary>Supabase CLI を使う場合（開発者向け）</summary>

```bash
npm install -g supabase
supabase link --project-ref <あなたのプロジェクトID>
supabase db push
```

`supabase/migrations/` の SQL が順番に適用されます。
</details>

### 3-3. 「Confirm email」をオフにする（**必須**）

このアプリはメールアドレスを入力させません。合言葉から内部用のアドレスを自動で作って使うため、
確認メールの送信をオフにする必要があります。

1. 左メニューの「**Authentication**」→「**Sign In / Providers**」を開きます。
2. 「**Email**」を開きます（初期状態で有効になっています）。
3. 「**Confirm email**」を **オフ** にして保存します。

> この設定を忘れると、「はじめる」を押したときに
> 「Supabase の設定で「Confirm email」をオフにしてください」と表示されます。

> このアプリはメールでの確認・パスワード再設定・招待リンクのいずれも使わないため、
> Supabase の「URL Configuration」（Site URL / Redirect URLs）は設定不要です。

## 4. 環境変数の設定方法

「環境変数」とは、**アプリに教えるパスワードや接続先のメモ**のことです。
ソースコードに直接書かずにファイルへ分けることで、誤って公開してしまう事故を防ぎます。

### 4-1. 値を確認する

Supabase の左メニュー「**Project Settings**」→「**API Keys**」（または Data API）を開き、次の2つを控えます。

| 表示名 | 使う場所 |
| --- | --- |
| **Project URL**（`https://xxxx.supabase.co`） | `NEXT_PUBLIC_SUPABASE_URL` |
| **anon public**（`eyJhbGci...` で始まる長い文字列） | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |

> `service_role` キーは**絶対に使わないでください**。このアプリでは不要です。
> 万一これを公開すると、すべてのデータが誰でも読み書きできる状態になります。

### 4-2. ファイルを作る

`kakeibo` フォルダの中の `.env.example` をコピーして、`.env.local` という名前で保存します。

```bash
# Windows (PowerShell)
Copy-Item kakeibo/.env.example kakeibo/.env.local
```

```bash
# Mac / Linux
cp kakeibo/.env.example kakeibo/.env.local
```

`.env.local` をメモ帳などで開き、次のように書き換えます。

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

> `.env.local` は Git に保存されない設定になっています（`.gitignore` 済み）。
> このファイルを他人に送ったり、SNS に貼ったりしないでください。

## 5. ローカルでの起動方法

```bash
# 1. 必要な部品をダウンロード（初回のみ・数分かかります）
npm install --prefix kakeibo

# 2. 起動
npm run dev --prefix kakeibo
```

ブラウザで <http://localhost:3000> を開きます。停止するときはターミナルで `Ctrl + C` を押します。

### 初回の使い方（合言葉）

1. 最初の画面で「**家計の合言葉**」と「**お名前**」を入れて「はじめる」を押します。
   合言葉が思いつかないときは「合言葉の候補を出す」を押してください。
2. これで新しい家計簿ができます。**合言葉をパートナーに伝えてください**（設定画面でいつでも確認できます）。
3. パートナーは自分の端末で、**同じ合言葉**と**自分のお名前**を入れて「はじめる」を押します。
4. これで2人が同じ家計簿を使えるようになります。

| 場面 | 入れるもの |
| --- | --- |
| はじめて使う | 新しく決めた合言葉 ＋ 自分の名前 |
| パートナーが参加する | **同じ**合言葉 ＋ **自分の**名前 |
| 機種変更・アプリを入れ直した | **同じ**合言葉 ＋ **同じ**自分の名前 |

> **合言葉とお名前は必ず控えておいてください。**
> この2つが「鍵」になっていて、忘れると入り直せません（メールでの再設定はありません）。
> 相手が使えている場合は、相手が設定画面で合言葉を確認できます。

> 合言葉を知っている人は、あなたの家計簿を見られます。
> 他の人に教えない、推測されにくい言葉にする、の2点にご注意ください。

## 6. iPhone のホーム画面に追加する方法

1. iPhone の **Safari** でアプリのURLを開きます（Chrome ではなく Safari である必要があります）。
2. 画面下部の **共有ボタン**（□に↑のアイコン）をタップします。
3. メニューを下にスクロールし、「**ホーム画面に追加**」をタップします。
4. 名前（「家計簿」）を確認して、右上の「**追加**」をタップします。

ホーム画面のアイコンから起動すると、Safari のアドレスバーが消えて**アプリと同じ全画面表示**になります。
iPhone のノッチやホームバーを避けた表示（セーフエリア対応）にも対応しています。

> ローカル（`http://localhost:3000`）ではホーム画面追加が正しく動かないことがあります。
> 7章の手順で公開してから追加してください。

## 7. インターネットに公開する方法

もっとも簡単なのは **Vercel** です。

1. このプロジェクトを GitHub にアップロードします。
2. <https://vercel.com/> にログインし、「**Add New... → Project**」から GitHub のリポジトリを選びます。
3. **Root Directory** に `kakeibo` を指定します（このフォルダがアプリ本体です）。
4. 「**Environment Variables**」に、4章で作った2つの値を登録します。
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
5. 「**Deploy**」を押します。数分で公開されます。

これだけで完了です（Supabase 側の追加設定は不要です）。

> 公開URLは**毎回同じURL**を使ってください。ブラウザの保存領域はURL単位のため、
> URL が変わるとデモモードのデータや、この端末に控えた合言葉が引き継がれません。

## 9. 画面と機能の一覧

画面下部に6つのタブが固定表示されます。**アプリを開くと一番左の「入力」が最初に開きます。**

| タブ | 主な内容 |
| --- | --- |
| **入力** | 支出・収入の登録欄。今月の残り予算を上に表示。保存しても画面は動かず、続けて登録できます |
| **ホーム** | 今月の予算・支出・残り予算・使用率、予算の円グラフ、カテゴリ別の円グラフ、直近5件、貯金目標、未完了Todo、最近のコメント、予算超過の警告。上部の**「2人合計／共有／自分／相手」**で集計対象を切り替えられます |
| **家計簿** | **カレンダー**（日ごとの支出・収入）、月別の一覧、絞り込み（カテゴリ・支払者・共有/個人）、キーワード検索、複製登録、定期支出の確認候補 |
| **貯金** | 目標の一覧・作成、進捗バー、達成率、あといくら、月あたりの積立目安、入金／取り崩しの履歴 |
| **共有** | 「Todo」と「コメント」を切り替え（**Todo が先に開きます**）。コメントには**いいね**と**返信**ができます。個人モードでは自分用メモ・自分用Todoとして使えます |
| **設定** | 表示名、合言葉の確認・変更、月の開始日、予算繰越し、カテゴリ管理、定期支出管理、ダークモード、通知、CSV出力、退出・削除 |

そのほかの画面: 予算管理（`/budget`）、履歴・集計（`/stats`）、最初の画面（`/start`）。

### 支出登録は3タップから

アプリを開く → 金額をテンキーで入力 → よく使うカテゴリをタップ → 保存。
日付（今日）・支払者（自分）・区分（共有）・支払方法（前回と同じ）は初期値が入っているため、
変更が不要ならそのまま保存できます。保存後は入力欄だけが空になり、続けて登録できます。

### カレンダー（家計簿タブ）

集計期間のカレンダーに、その日の支出（と収入）が金額そのままで表示されます。
使った額が多い日ほど背景が濃くなるので、出費が集中した日が一目で分かります。
日付をタップすると、その日の記録だけに絞り込めます（もう一度タップで解除）。

右上のプルダウンで表示対象を切り替えられます。

| 選択 | 表示される内容 |
| --- | --- |
| 2人合計 | 共有と2人の個人支出、すべて |
| 共有のみ | 家計から出したお金だけ |
| 自分の個人 | 自分が個人で払った分だけ |
| 相手の個人 | 相手が個人で払った分だけ |

### カテゴリ別の推移（履歴・集計）

「月別の支出推移」の棒グラフの上にあるプルダウンでカテゴリを選ぶと、
そのカテゴリだけの6ヶ月分の推移に切り替わります（棒の色もそのカテゴリの色になります）。
下の「前月との差」もあわせて、選んだカテゴリの数字に変わります。

## 10. データベース構成

詳しい説明は [docs/DATABASE.md](docs/DATABASE.md) にあります。ここでは要点だけ示します。

```
households（家計グループ）
  ├─ household_members（メンバー・最大2人）
  ├─ categories（カテゴリ）
  ├─ budgets（予算：全体／個人／カテゴリ別）
  ├─ transactions（支出・収入）
  ├─ recurring_rules（定期支出）
  ├─ savings_goals（貯金目標）─ savings_entries（入金・出金履歴）
  ├─ todos（Todo）
  └─ comments（コメント）─ comment_reads（既読位置）
profiles（表示名・入り直すときのお名前）
```

**安全の仕組み（Row Level Security）**

- すべてのテーブルで RLS を有効にしています。ポリシーがない操作は実行できません。
- データを読めるのは「**自分がそのグループのメンバーであるとき**」だけです。
  参加していない人は、URL や ID を知っていてもデータを取得できません。
- 個人の貯金目標（`scope = 'personal'`）は、**所有者本人以外には結果すら返りません**。
- メンバーの追加・合言葉の変更・パートナー解除などは、ブラウザから直接テーブルを書き換えられないようにし、
  サーバー側の関数（`join_or_create_household` など）でのみ実行できるようにしています。
- 合言葉の照合用の値（`passphrase_hash`）は、ブラウザからは読むことも書くこともできません。
- 金額は `bigint`（円単位の整数）で保存し、`amount_yen > 0` をデータベース側でも強制しています。

## 11. 設計上の判断メモ

要件で明示されていなかった点は、一般的な家計簿アプリとして自然な形に決めました。

| 判断したこと | 決めた内容と理由 |
| --- | --- |
| 個人モードのデータ構造 | 個人モードでも「1人だけの家計グループ」を作ります。共有モードへの移行が合言葉を伝えるだけで済み、アクセス制御も「グループのメンバーか」の1点に統一できます |
| 個人／共有モードの切り替え | 画面で選ばせず、**メンバーが2人になった時点で自動的に共有モード**になります（余計な質問を減らすため） |
| 起動時の画面 | 一番左のタブを「入力」にし、`/` を入力画面にしています。家計簿アプリで最も回数の多い操作が入力のためです。ホーム（残り予算のまとめ）は2番目のタブです |
| 保存後の動き | 入力タブから保存したときは画面を移動せず、金額と内容だけを空にします。レシートをまとめて入力する場面で押しやすいためです |
| 「共有／個人」区分の意味 | これは**家計の支出か、自分個人の支出か**という分類です。共有モードでは、どちらの区分もパートナーが閲覧できます（家計の全体像を2人で共有するため）。他人に見せたくない目標は「個人目標」を使います |
| 共有の**支出**の「支払った人」 | 共有は**誰の支払いでもない（家計から出したお金）**として記録します。データ上は `paid_by` を空にしており、「誰がいくら払ったか」では個人ではなく「共有（家計から）」としてまとめます。入力した人ひとりに共有支出が積み上がって見えるのを防ぐためです |
| 共有の**収入**の「受け取った人」 | 収入は共有でも**人を選べます**（誰の収入かは家計の把握に必要なため）。入力欄の名前も収入のときは「受け取った人」に変わります。支出側の集計には影響しません |
| 誰が使ったかを見る方法 | 個人の支出だけが人に紐づきます。ホームの上部と家計簿タブのカレンダー右上で「2人合計／共有／自分／相手」を切り替えると、誰がいつ使ったかを確認できます |
| コメントの返信・いいね | 返信は1段階までにしています（深い階層はスマホで読みにくいため）。いいねは1人1コメント1回で、押した人の名前は長押し（ホバー）で確認できます |
| 個人の貯金目標 | `scope='personal'` の目標は所有者本人だけが閲覧・編集できます（RLS で強制） |
| 相手の記録の編集 | 同じグループのメンバーは相手の記録も修正できます（レシートを見ながら片方がまとめて直せるように）。ただし `created_by` / `updated_by` を必ず記録し、詳細画面に「登録: ◯◯」「更新: ◯◯」と表示します |
| コメントの編集・削除 | 投稿者本人のみ可能です |
| 「月の開始日」の解釈 | 開始日が25日なら「2026年8月」＝ **2026-08-25 〜 2026-09-24** です（その月の開始日から翌月の開始日の前日まで）。29日以降は存在しない月があるため、設定できるのは1〜28日です |
| 予算の繰越し | 初期状態はオフ。オンにすると**前月1ヶ月分だけ**の残額（超過ならマイナス）を加算します。何ヶ月も遡って累積はしません |
| 予算の通知 | アプリ内の警告表示のみです。80%・100%到達時にホーム画面上部へ表示し、閉じるとその月は再表示しません。端末へのプッシュ通知は行いません |
| 定期支出 | 自動では登録しません。家計簿画面に「今月の確認候補」として表示し、「登録する」を押したときだけ記録されます。似た金額・カテゴリの記録が既にある場合は重複の可能性を知らせます |
| 貯金カテゴリとの連携 | 支出登録で貯金目標を選んだとき、カテゴリが「貯金」なら**入金**として、それ以外なら**取り崩し**として貯金履歴に記録します（画面上にも明記しています） |
| ログイン方法 | メールアドレスとパスワードは使いません。「合言葉 + お名前」から、ログイン用のアドレスとパスワードをその場で計算します（PBKDF2）。合言葉そのものはサーバーに送らず、照合用の値だけを保存します |
| なぜ「お名前」も必要か | 合言葉だけだと2人が同じアカウントになってしまい、「どちらが払ったか」を区別できません。お名前を混ぜることで、同じ家計の中で別々の利用者になります |
| 表示名とお名前 | 「入り直すときのお名前」は変わりません。設定画面で変えられる「表示名」は画面表示だけに使います（うっかり入れなくなるのを防ぐため分けています） |
| 合言葉の変更 | **1人で使っているときだけ**変更できます。2人で使っている間に変えると相手が入れなくなるため、あえて禁止しています |
| パートナー解除 | 共有データは**残ります**。解除しただけでは相手が同じ合言葉で入り直せてしまうため、**解除と同時に新しい合言葉を決めてもらいます** |
| 合言葉を忘れたら | 復旧できません（メールでの再設定はありません）。相手が使えていれば、相手の設定画面で合言葉を確認できます |
| アカウント削除 | 相手が残っている場合、共有データは残します（相手のデータを消さないため）。1人だけの場合はグループごと削除します。どちらも確認画面と「削除する」の入力確認があります |
| 削除の取り消し | 支出と貯金履歴の削除後、**7秒間**「元に戻す」を表示します |
| カテゴリの削除 | 初期カテゴリと、既に使われているカテゴリは削除できません（データベース側でも拒否）。代わりに「非表示」にできます |
| グラフ | 外部のグラフライブラリは使わず SVG で描いています。凡例にカテゴリ名・金額・割合を必ず文字で出すため、色が判別しにくい場合でも内容が分かります |
| 選択メニュー | 端末標準の `<select>` を使っています。iPhone では OS のホイールピッカーが開き、片手でもっとも操作しやすいためです |
| 認証まわり | 内部的には Supabase Auth のメール＋パスワードを使いますが、その値は合言葉とお名前から自動生成し、利用者には見せません。SNS ログインは対象外です |
| カレンダーの並び | 暦月ではなく「集計期間」を描きます。月の開始日を25日にしている場合も、8/25〜9/24 が途切れずに並びます |

## 13. 困ったときは

| 症状 | 対処 |
| --- | --- |
| 「Supabase の環境変数が設定されていません」と出る | `.env.local` の作成漏れです。4章を確認し、作成後に開発サーバーを再起動してください |
| 「Confirm email をオフにしてください」と出る | Supabase の Authentication 設定です。3-3章の手順で確認メールをオフにしてください |
| 入れるがデータが表示されない | `0003_rls.sql` が未実行の可能性があります。SQL Editor で実行してください |
| パートナーの変更が反映されない | `0004_realtime.sql` が未実行の可能性があります |
| 「すでに2人が参加しています」と出る | 合言葉の打ち間違いで、別の家計に入ろうとしている可能性があります。合言葉をもう一度ご確認ください |
| パートナーのはずが、別の家計簿になってしまう | 合言葉が1文字でも違うと別の家計になります。設定画面で合言葉をコピーして送ってもらってください |
| 自分の記録が「別の人」として登録される | お名前の打ち間違いです。前回と同じお名前で入り直してください |
| 合言葉を忘れた | 相手が使えていれば、相手の設定画面で確認できます。2人とも忘れた場合は復旧できません |
| ホーム画面に追加できない | iPhone の **Safari** で開いているか、`https://` で公開されているかを確認してください |
| Windows + OneDrive でビルドが `EPERM` で失敗する | 開発サーバーを停止し、`kakeibo/.next` フォルダを削除してから再実行してください |
| デモモードのデータを初期状態に戻したい | 設定 →「デモモードを終了」→ 再度デモモードに入ると、サンプルデータが作り直されます |

## 技術構成

- **Next.js 15**（App Router）/ **TypeScript** / **Tailwind CSS v4**
- **shadcn/ui 方式のコンポーネント**（Radix UI + class-variance-authority を同梱。CLI 生成物と同等のものを `src/components/ui/` に直接置いています）
- **Supabase**（Authentication / PostgreSQL / Realtime / Row Level Security）
- **PWA**（`public/manifest.webmanifest` + `public/sw.js`。アイコンは `npm run icons` で再生成できます）
- **Vitest**（テスト）

```
kakeibo/
├─ src/
│  ├─ app/            画面（App Router）
│  ├─ components/     UI 部品
│  └─ lib/            計算・検証・データアクセス（画面から独立、テスト対象）
├─ supabase/migrations/   データベース定義とセキュリティ設定
├─ tests/             自動テスト
├─ scripts/           PWA アイコン生成
└─ public/            マニフェスト・Service Worker・アイコン
```
